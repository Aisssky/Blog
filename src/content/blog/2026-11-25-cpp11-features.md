## C++标准

C++标准到目前为止，已经包括了C++98，C++11，C++14，C++17，C++20。从名字上就可以看到，自从C++11开始，C++语言就进入了发展的快车道，是每三年就发布了一版标准。多个标准的发布也使C++的语法，标准库开始膨胀。

C++ 11 是C++语言的一个分水岭，标志着C++语言开始向现代化语言(更简单，更易用，开发效率更高)迈进。C++ 11 之前的C++ 98可以说等于C语言+基本的面向对象元素，并且它的标准库非常弱，也涌现出了大量的“轮子”。 C++11对C++语言的可以说是脱胎换骨的改造，搭起了“骨骼”，后面几个标准是“赋之皮肉”。

C++ 偏向底层应用，再加上语法复杂，很多时候都让人望而却步。但是在一些场景(领域)它无可替代。对C++我们应该专注于能提高开发效率及可维护性的核心语言机制，而非大而全的去掌握所有的C++语法及语言机制，这样就像是用大炮打蚊子。C++ 11标准发布后，相较以往，开发效率得到了大大的提升。C++11引入的语言新特性理应成为C++的核心语言机制。

## 内存管理及C++RAII手法

### 基本概念

#### 堆(heap)

指的是动态分配内存的区域。操作堆用以下两种方式进行：

- new和delete

- malloc和free

#### 栈(stack)

指的是函数调用过程中产生的本地变量和调用数据区域。这个栈和数据结构的栈相似，都满足后进先出

### RAII（Resource Acquisition Is Initialization资源获取即初始化）

**用对象（栈上的局部变量）的生命周期，去绑定并管理某种资源（堆内存、文件句柄、锁）。**

- **获取资源：在对象的构造函数中完成。**

- **释放资源：在对象的析构函数中完成。**

C++所特有的资源管理方式，它依托栈和析构函数，来对所有的资源（包括堆内存在内）进行管理。

它提供了一种异常安全的资源管理方式，对RAII的使用，使C++不需要类似于Java那样的垃圾收集方法，JavaGC是后台有一个专门的线程在跑，时不时去扫描哪些对象没人用了。这会带来不可控的停顿。打游戏的时候会卡一下往往就是因为 Java 在搞 GC。

而C++的RAII是确定性释放，没有运行时开销，到期立刻释放，性能极高，也能有效的内存进行管理。

## 智能指针

- 智能指针的基本原理就是通过 RAII 实现对内存的管理，从 C++11 开始已经不推荐再使用裸指针。

- 智能指针支持裸指针的所有操作，如：`*`，`++`，`--`，`+=`，`<`，`>`。

- C++ 11 加入了` shared_ptr`，`unique_ptr`，`weak_ptr`，（还可以算上 Boost 库中的` scoped_ptr`\)，三种智能指针都有各自的语义，对所管理的对象代表了不同所有权，适用于不同的场景。

#### `shared_ptr`

共享所有权，具有复制语义，多个shared_ptr指向同一个对象时，每个shared_ptr的引用**计数**都会记录指向该对象的shared_ptr的数量，当最后一个指向对象（和共享计数）的shared_ptr析构时，它会删除对象和共享计数，通过use_count方法可以获取shared_ptr对象的共享计数值。

##### **细节**

- 底层

    - `std::shared_ptr` 的尺寸大于裸指针，一般是裸指针的两倍，因为它内部既包含一个指向到资源的裸指针，也包含一个指向该资源的引用计数的裸指针。

        `shared_ptr` 底层包含两个指针：

    1. 指向对象的指针：用 `*` 和 `->` 操作的那个目标对象。

    2. 指向控制块（Control Block）的指针：控制块里存着引用计数（Strong Count）、弱引用计数（Weak Count）以及分配器和删除器等。

    ```C++
    template<class T>
    class shared_ptr {
    private:
        T* ptr;                  // 1. 指向真实对象的裸指针
        ControlBlock* ctrl;      // 2. 指向控制块（引用计数）的裸指针
        //ControlBlock里有强引用计数（shared count）、弱引用计数（weak count），以及删除器（deleter）和分配器（allocator）
    };
    ```

    - 控制块的创建：

        - `std::make_shared` 总是创建一个控制块

        - 从具备专属所有权的指针(`std::unique_ptr`)构造一个 `std::shared_ptr` 时，会创建一个控制块

        - 当 `std::shared_ptr` 构造函数使用裸指针作为实参来调用时，它会创建一个控制块

    - 创建 shared_ptr 应该优先使用 make_shared：

        - 只会产生一次内存分配，对象与计数对象共用一块区域（红圈标出）

        - 效率更高

        - 异常安全的构造 shared_ptr

- 引用计数的内存是动态分配的。

- 引用计数的递增和递减是原子操作。

**注意**

- **引用计数的线程安全**：shared_ptr 的引用计数加减是原子操作（atomic），是线程安全的。也就是说，多个线程同时拷贝同一个 shared_ptr，计数不会乱。但是！ **它指向的那个对象本身，并不是线程安全的**。

- **循环引用（死锁）**：假设有两个类 A 和 B，A 里有一个 `shared_ptr<B>`，B 里有一个 `shared_ptr<A>`。当你把它们互相赋值后，引用计数永远不会归零，即使你离开作用域，这个对象也无法被释放，直接内存泄漏。这就是为什么我们需要 `weak_ptr` 的原因。
（面雷火的时候就是问的这个……）

#### `weak_ptr`

`shared_ptr` 的终极补丁，用来表示临时所有权(弱引用，不会增加引用计数)，它需要配合shared_ptr使用，追踪shared_ptr所管理的对象是否有效，当需要临时所有权时，则将其转换为shared_ptr，这样对象的引用计数会加1，来保证正在访问的对象有效性，它有三个关键方法:`use_count()`, `expired()`,` lock()`

weak_ptr具有复制语义，可以通过一个weak_ptr对象构造另一个weak_ptr对象，通过一个shared_ptr构造一个weak_ptr对象

##### weak_ptr与shared_ptr

- 在多线程程序中通过裸指针来管理共享对象是一个很让人头疼的场景，最大的困难之处就是保证共享对象的有效性和共享对象的有效性的检测。一不小心就会造成共享对象被某个线程释放，而造成线程访问无效内存导致程序崩溃的问题。那么在C++ 11 中通过weak_ptr与shared_ptr的结合可以很方便的在多线程环境下检测，管理共享对象的有效性。
